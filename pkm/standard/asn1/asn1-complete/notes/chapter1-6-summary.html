第六章总结：使用 ASN.1 编译器实现协议

核心内容：几种实现方法的对比，重点介绍 ASN.1 编译器工具的使用和工作原理。

1. 三种实现方法

方法 描述 适用性
手写编解码 自写所有编解码代码 仅极简单的规范，不推荐
通用库调用 调用预置的编解码库函数（如 encode_untagged_int()） 适合 BER，不适合 PER；需手动处理 TLV 嵌套和长度
ASN.1 编译器工具 编译 ASN.1 → 生成语言数据结构 + 控制表；填充数据后调用 ENCODE/ DECODE 推荐方案，支持所有编码规则

2. ASN.1 编译器工具工作原理

ASN.1 模块 → [编译器] → .h (数据结构) + .c (控制表/代码)
                             ↓
                    应用程序代码 → 填充结构 → 调用 ENCODE
                    接收消息 → 调用 DECODE → 读取结构
  • CompilerInfo：由编译器生成的控制信息，包含标签、DEFAULT 处理等全部类型信息，运行时编解码库依赖它
  • 表驱动 vs 开放代码：
  • 表驱动：内存小，速度慢
  • 开放代码：内存大，速度快

3. 手写编码的难点（通用库方法）

  • 编码 SEQUENCE 前需知道总长度 → 需要试编码、不定长度形式、预分配或缓冲链
  • 嵌套结构使代码复杂且难以维护
  • 解码需要通用解析器 → 解析 BER 树 → 遍历提取值

4. 选择编译器工具的关键因素

因素 说明
平台支持 硬件、OS、语言（C/C++/Java）；交叉编译可选
ASN.1 完整支持 多模块、IMPORTS/EXPORTS、1994 扩展（信息对象类）、值记法、DEFAULT
整数映射 可控制映射为 short / int / long / big integer
性能选择 内存 vs 速度的权衡选项
用户控制 全局指令 + 局部覆盖（如 SET -- <LINKED> -- OF INTEGER）
运行时可选编码规则 BER/PER/DER/CER 等
成本 通常一次性许可费 + 无限运行时分发许可

一句话总结

使用 ASN.1 编译器工具 = 写 ASN.1 → 编译生成数据结构 → 填充数据 → 调用 ENCODE/DECODE，是最简单、最可靠的方式。
