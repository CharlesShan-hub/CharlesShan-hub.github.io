### 7.3.1 Modelling the food order event in Avro

The first module, domain-schema, contains all of the Avro schema definitions for the GottaEat order entry use case. Avro schemas can be defined in either plain JSON or Avro IDL text files, but the schema files need to live somewhere, and this module serves that purpose.

第一个模块 domain-schema 包含了 GottaEat 订单录入用例所需的全部 Avro schema 定义。Avro schema 既可以用普通 JSON 来定义，也可以用 Avro IDL 文本文件来定义，但这些 schema 文件总得有个存放的地方，这个模块就是干这个的。

As you can see from the contents of the domain-schema module, I have created an Avro IDL schema definition file named src/main/resources/avro/order/food-order.avdl, which contains the schema definition shown in listing 7.2. This file represents the initial data model for the food order object that will be used across multiple services, and it will be used to generate the Java classes that will be used by all of the consuming Java-based microservices.

从 domain-schema 模块的内容可以看到，我创建了一个 Avro IDL schema 定义文件，名为 src/main/resources/avro/order/food-order.avdl，其中包含清单 7.2 中所示的 schema 定义。这个文件代表了餐品订单对象的初始数据模型，它将被多个服务共用，并且会被用来生成供所有基于 Java 的消费方微服务使用的 Java 类。

Listing 7.2 food-order.avdl

```java
@namespace("com.gottaeat.domain.order")                       ❶
protocol OrderProtocol {
  import idl "../common/common.avdl";                         ❷
  import idl "../payment/payment-commons.avdl";
  import idl "../resturant/resturant.avdl";
  
  record FoodOrder {                                          ❸
    long order_id;
    long customer_id;    
    long resturant_id;    
    string time_placed;    
    OrderStatus order_status;
    array<OrderDetail> details;                               ❹
    com.gottaeat.domain.common.Address delivery_location;     ❺
    com.gottaeat.domain.payment.CreditCard payment_method;
    float total = 0.0;
  }
  
  record OrderDetail {
     int quantity;
     float total;
     com.gottaeat.domain.resturant.MenuItem food_item;
  }
  
  enum OrderStatus {
    NEW, ACCEPTED, READY, DISPATCHED, DELIVERED
  }
}
```

❶ The namespace for these types, which corresponds with the Java package name

❶ 这些类型所属的命名空间，它与 Java 的包名相对应。

❷ We import Avro type definitions from other files, which enables compositional schemas.

❷ 我们从其他文件中导入 Avro 类型定义，这使得可组合的 schema 成为可能。

❸ The FoodOrder record definition

❸ FoodOrder 记录的定义。

❹ Each FoodOrder can contain one or more food items in it.

❹ 每一份 FoodOrder 中可以包含一项或多项餐品。

❺ Using a type defined inside one of the included schema definitions

❺ 使用某个被引入的 schema 定义中所定义的类型。

We will use the Avro plugin to automatically generate Java classes based on the schema definitions in our project by adding the configuration shown in the following listing to the plugins section of the Maven pom.xml file.

我们将使用 Avro 插件，基于项目中的 schema 定义自动生成 Java 类。具体做法是：把下面清单中所示的配置添加到 Maven pom.xml 文件的 plugins 段中。

Listing 7.3 Configuring the Avro Maven plugin

```xml
<plugin>
  <groupId>org.apache.avro</groupId>
  <artifactId>avro-maven-plugin</artifactId>
  <version>1.9.1</version>
  <executions>
     <execution>
       <phase>generate-sources</phase>                        ❶
       <goals>
          <goal>idl-protocol</goal>                           ❷
       </goals>
       <configuration>
        <sourceDirectory>
          ${project.basedir}/src/main/resources/avro/order    ❸
         </sourceDirectory>
         <outputDirectory>
            ${project.basedir}/src/main/java                  ❹
          </outputDirectory>
       </configuration>
    </execution>
  </executions>
</plugin>
```

❶ We want to generate Java source files.

❶ 我们希望生成 Java 源文件。

❷ The definitions are in the IDL format.

❷ 这些定义采用的是 IDL 格式。

❸ Use the directory containing the food-order.avdl as the source directory.

❸ 把包含 food-order.avdl 的那个目录用作源目录。

❹ Where to output the generated source files

❹ 生成的源文件输出到哪里。

With the Avro schemas defined and the Maven plugin configured, we can execute the command shown in listing 7.4 to generate the Java classes into the project’s source folder, as specified in listing 7.3. This command will generate the Java classes source files, compile them, and jar them into the domain-schema-0.0.1.jar JAR file before finally publishing that JAR file to your local Maven repository.

Avro schema 定义好、Maven 插件也配置好之后，我们就可以执行清单 7.4 中所示的命令，把 Java 类生成到项目的源码目录中（正如清单 7.3 所指定的那样）。这条命令会生成 Java 类的源文件、编译它们，并把它们打成 domain-schema-0.0.1.jar 这个 JAR 文件，最后再把这个 JAR 文件发布到你本地的 Maven 仓库。

You will find the generated classes inside their respective subfolders, under the project’s source folder, as shown in listing 7.5. These files are too lengthy to reproduce here, but if you open them with a text editor, you will see that the files contain POJOs that have been auto-generated by Avro and contain all the field definitions in the schema definitions, along with methods to serialize and deserialize the object to and from Avro’s binary format.

你会发现生成的那些类位于项目源码目录下的各自子文件夹中，如清单 7.5 所示。这些文件太长，不适合在这里原样复制，但如果你用文本编辑器打开它们，就会看到其中包含由 Avro 自动生成的 POJO：它们含有 schema 定义中的全部字段定义，以及用于把该对象序列化成 Avro 二进制格式、和从 Avro 二进制格式反序列化回来的方法。

到这里，我们就拥有了一个用 Java 描述的餐品订单事件领域模型，项目中其他的微服务都可以使用它。
