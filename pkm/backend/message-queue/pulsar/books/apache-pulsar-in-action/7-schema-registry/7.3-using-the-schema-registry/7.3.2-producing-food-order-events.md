### 7.3.2 Producing food order events

Rather than create a dependency on the customer mobile application that is being developed by a different team, we have decided to use this tool to generate load for testing purposes. The customer-mobile-app-simulator module contains an IO Connector intended to simulate the mobile application that customers will use to place food orders. The connector is defined inside the CustomerSimulatorSource class, as shown in the following listing.

与其去依赖另一个团队正在开发的客户移动应用，我们决定用这个工具来生成测试所需的负载。customer-mobile-app-simulator 模块中包含了一个 IO 连接器，用来模拟客户下单时所用的那个移动应用。该连接器定义在 CustomerSimulatorSource 类中，如下面清单所示。

Listing 7.6 The CustomerSimulatorSource IO connector

```java
import org.apache.pulsar.io.core.Source;
import org.apache.pulsar.io.core.SourceContext;
public class CustomerSimulatorSource implements Source<FoodOrder> {       ❶

  private DataGenerator<FoodOrder> generator = new FoodOrderGenerator();  ❷
    
  @Override
  public void close() throws Exception {
  }

  @Override
  public void open(Map<String, Object> map, SourceContext ctx) 
      throws Exception {

  }

  @Override
  public Record<FoodOrder> read() throws Exception {
     Thread.sleep(500);                                                   ❸
  return new CustomerRecord<FoodOrder>(generator.generate());             ❹
  }
        
  static private class CustomerRecord<V> implements Record<FoodOrder> {   ❺
    ...
  }
        
  ...                                                                     ❻
}
```

❶ Implements the source interface, which defines the three overridden methods

❶ 实现了 source 接口，该接口定义了那三个被重写的方法。

❷ The class that produces random food orders

❷ 负责生成随机餐品订单的那个类。

❸ Pause a half second between orders.

❸ 每两个订单之间暂停半秒。

❹ Publishes a newly generated food order to the output topic

❹ 把一条新生成的餐品订单发布到输出主题。

❺ A wrapper class for sending the FoodOrder objects

❺ 一个用于发送 FoodOrder 对象的包装类。

❻ Where the LocalRunner code lives

❻ LocalRunner 代码所在的位置。

As you may recall from chapter 5, the source connector’s read method is invoked by Pulsar’s internal function framework repeatedly, and the return value gets published to the configured output topic. In this case, the return value is a random food order based on the Avro schemas in the domain-schema module generated by another class inside the project, named FoodOrderGenerator. I have decided to use the LocalRunner for debugging the CustomerSimulatorSource class, as shown in the following listing.

你应该还记得第 5 章讲过：source 连接器的 read 方法会被 Pulsar 内部的函数框架反复调用，其返回值会被发布到所配置的输出主题上。在本例中，返回值是基于 domain-schema 模块中 Avro schema 生成的一份随机餐品订单，它由项目内另一个名为 FoodOrderGenerator 的类产生。我决定使用 LocalRunner 来调试 CustomerSimulatorSource 类，如下面清单所示。

Listing 7.7 Using LocalRunner to debug the CustomerSimulatorSource IO connector

```java
...
public static void main(String[] args) throws Exception {
  SourceConfig sourceConfig = SourceConfig.builder()
    .className(CustomerSimulatorSource.class.getName())                      ❶
    .name("mobile-app-simulator")
    .topicName("persistent://orders/inbound/food-orders")                    ❷
    .schemaType("avro")
    .build();
        
  // Assumes you started docker container with --volume=${HOME}/exchange 
  String credentials_path = System.getProperty("user.home") +
                       File.separator + "exchange" + File.separator;

  LocalRunner localRunner = LocalRunner.builder()
  .brokerServiceUrl("pulsar+ssl://localhost:6651")                           ❸
  .clientAuthPlugin("org.apache.pulsar.client.impl.auth.AuthenticationTls")
  .clientAuthParams("tlsCertFile:" + credentials_path + 
       "admin.cert.pem,tlsKeyFile:" + credentials_path + "admin-pk8.pem") 
  .tlsTrustCertFilePath(credentials_path + "ca.cert.pem")                    ❹
  .sourceConfig(sourceConfig)
  .build();
        
  localRunner.start(false);                                                  ❺
  Thread.sleep(30 * 1000);
  localRunner.stop();                                                        ❻
   
}
```

❶ Specify the connector class we want to run.

❶ 指定我们想要运行的那个连接器类。

❷ The topic the connector will publish messages to

❷ 该连接器将把消息发布到的那个主题。

❸ Specify the URL of the Pulsar broker we are going to interact with.

❸ 指定我们要与之交互的那个 Pulsar broker 的 URL。

❹ Specify the TLS authentication credentials needed to connect to Pulsar.

❹ 指定连接 Pulsar 所需的 TLS 认证凭据。

❺ Starts the LocalRunner

❺ 启动 LocalRunner。

❻ Stops the LocalRunner

❻ 停止 LocalRunner。

As you can see from listing 7.7, I have configured the LocalRunner to connect to a locally running instance of the pulsar-standalone-secure Docker image that I created in chapter 6. This is why there are several security-related configuration settings in the source code that rely on the security credentials generated for that container, such as the TLS client certificate and trust store.

从清单 7.7 中可以看到，我把 LocalRunner 配置为连接到一个本地运行的 pulsar-standalone-secure Docker 镜像实例——那是我在第 6 章中创建的镜像。正因如此，源码中才会有若干与安全相关的配置项，它们依赖于为该容器所生成的那些安全凭据，例如 TLS 客户端证书和信任库。
