### 7.3.3 Consuming the food order events

Lastly, let’s look at the order-validation-service module, which contains a single Pulsar function, named OrderValidationService, which, for the purposes of this chapter, will be just a skeletal implementation of the microservice shown in figure 7.12 and will accept the incoming food orders and validate them for correctness and confirmation of payment, etc. Over time, additional logic will be added, but for now, the function will simply write all of the food orders it receives to standard output (stdout) before forwarding to the configured output topic.

最后，我们来看看 order-validation-service 模块，它包含唯一一个 Pulsar 函数，名为 OrderValidationService。就本章而言，它只是图 7.12 中那个微服务的一个骨架实现：接收 incoming 的餐品订单，并校验其正确性、确认付款是否成功等。随着时间的推移会陆续加入更多逻辑，但就目前来说，这个函数只是把收到的所有餐品订单写到标准输出（stdout），然后转发到所配置的输出主题。

Listing 7.8 The OrderValidationService function

```java
import org.apache.pulsar.functions.api.Context;

public class OrderValidationService implements Function<FoodOrder, FoodOrder> {

    System.out.println(order.toString());
    return order;
}
```

This class also includes a main method that contains a LocalRunner configuration, so we can debug this class locally, as shown in the following listing.

这个类还包含一个 main 方法，其中带有一份 LocalRunner 配置，这样我们就能在本地调试这个类，如下面清单所示。

Listing 7.9 The OrderValidationService LocalRunner code

```java
public static void main(String[] args) throws Exception {
        
  Map<String, ConsumerConfig> inputSpecs = 
    new HashMap<String, ConsumerConfig> ();

  FunctionConfig functionConfig = 
     FunctionConfig.builder()
      .className(OrderValidationService.class.getName())                 ❷
      .inputs(Collections.singleton(
          "persistent://orders/inbound/food-orders"))                    ❸

      .name("order-validation")
      .output("persistent://orders/inbound/valid-food-orders")           ❹
      .outputSchemaType("avro")
      .runtime(FunctionConfig.Runtime.JAVA)
      .build();
    
  // Assumes you started docker container with --volume=${HOME}/exchange 
  String credentials_path = System.getProperty("user.home") +
                       File.separator + "exchange" + File.separator;

  LocalRunner localRunner = LocalRunner.builder()
  .brokerServiceUrl("pulsar+ssl://localhost:6651")                       ❺
  .clientAuthPlugin("org.apache.pulsar.client.impl.auth.AuthenticationTls")

  .functionConfig(functionConfig)

}
```

As you can see from listing 7.8, we have configured the LocalRunner to connect to the same Pulsar instance. This is why there are several security-related configuration settings in the source code that rely on the security credentials generated inside that container, such as the TLS client certificate and trust store.

从清单 7.8 中可以看到，我们把 LocalRunner 配置为连接到同一个 Pulsar 实例。正因如此，源码中才会有若干与安全相关的配置项，它们依赖于那个容器内部所生成的那些安全凭据，例如 TLS 客户端证书和信任库。
