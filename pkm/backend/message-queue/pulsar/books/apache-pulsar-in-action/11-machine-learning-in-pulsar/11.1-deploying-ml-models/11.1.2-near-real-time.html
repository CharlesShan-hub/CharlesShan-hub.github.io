11.1.2 Near real-time

2026-10-08book

Utilizing a ML model to generate predictions on a case-by-case basis using data that is only available in the incoming payload is commonly referred to as near real-time processing. This type of processing is considerably more complex than batch processing, primarily due to the latency constraints placed on systems that need to serve the predictions.

利用一个 ML 模型、仅凭传入负载中才有的那些数据来逐条逐例地生成预测，通常被称为近乎实时的处理。这类处理比批处理要复杂得多，其主要原因在于：那些需要提供预测的系统被施加了延迟上的约束。

A perfect candidate for near real-time deployment is the estimated time-to-delivery component of the GottaEat food delivery service that provides an estimate of when the food will be delivered for every newly placed food order. Not only does the feature vector of this ML model depend on data provided as part of the order (i.e., the delivery address), but it also needs to generate the estimate within a few hundred milliseconds. In short, when deciding which of these execution modes to use for your ML models you should consider the following factors:

近乎实时部署的一个完美候选，就是 GottaEat 外卖服务中的"预计送达时间"组件——它为每一笔新下的餐品订单估计出餐品何时会被送到。这个 ML 模型的特征向量不仅依赖于作为订单一部分所提供的那些数据（也就是配送地址），而且它还必须在几百毫秒之内生成这个估计值。简而言之，在决定为自己的 ML 模型选用这两种执行模式中的哪一种时，你应当考虑以下这些因素：

  • The availability of all the data required in the model’s feature vector and where that data is stored. Whether all the data you need to execute the model is readily available in the system or if some of it is provided in the request itself.
    模型特征向量所需的全部数据是否可得，以及这些数据存放在哪里。也就是说：执行该模型所需的全部数据，是已经在系统中唾手可得，还是其中有部分是由请求本身提供的。

  • How quickly the accuracy of the recommendations degrades over time. Can you precompute the recommendation and reuse it for a specific period?
    这些推荐的准确度随时间退化的速度有多快。你能不能把推荐结果预先算好，并在一段特定时间内重复使用它？

  • How quickly you can retrieve all the data used in the feature vector. Is it stored in memory or on non-real-time systems, such as HDFS, traditional databases, and so on.
    你取回特征向量中所用全部数据的速度有多快。它是存放在内存中，还是存放在那些非实时的系统上，例如 HDFS、传统数据库等等。

As you might have guessed, Pulsar functions are great candidates for deploying your ML models in near real-time mode for a multitude of reasons. First and foremost, they get executed immediately when a request comes in and have direct access to the data provided as part of the request, which eliminates any processing and data lookup latency. Secondly, as we saw in the previous chapter, you can retrieve data from a variety of external data sources to populate the feature vector with any necessary data that exists outside of the request itself. Finally, and most importantly, is the flexibility Pulsar Functions provides when it comes to deployment options. The ability to write your functions in Java, Python, or Go allows your data science team to develop a model in the language/framework of their choice and still deploy it inside a Pulsar function using third-party libraries that are bundled with the function to execute the model at runtime.

正如你可能已经猜到的，Pulsar 函数是以近乎实时模式部署 ML 模型的绝佳候选，原因有很多条。首先也是最重要的一条：当请求进来时它们会立即被执行，并且能直接访问作为请求一部分所提供的那些数据，这消除了任何处理和数据查找上的延迟。其次，正如我们在上一章中所看到的，你可以从各种各样的外部数据源取回数据，用以把请求本身之外的任何必需数据填进特征向量。最后，也是最重要的一点，是 Pulsar Functions 在部署选项上所提供的灵活性。能够用 Java、Python 或 Go 来编写自己的函数，这让你们的数据科学团队可以用自己选定的语言/框架来开发模型，并且依然能把它部署在一个 Pulsar 函数内部——借助那些随函数一同打包、在运行时执行模型的第三方库。
