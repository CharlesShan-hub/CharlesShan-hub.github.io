5.2.1 Developing a sink connector

2026-10-08book

I will start with a very basic sink connector that receives an endless stream of string values and writes them to a local temp file, as shown in listing 5.5. While this sink connector does have some limitations, specifically that you cannot write an endless stream of data to a single file, it does serve as a good example that can be used to demonstrate the process of developing a Sink connector.

我将从一个非常基础的 sink 连接器开始，它接收一串源源不断的字符串值，并把它们写入一个本地临时文件，如清单 5.5 所示。虽然这个 sink 连接器确实有一些局限，具体来说你无法把无休无止的数据流写入单个文件，但它作为一个不错的示例，足以用来演示开发一个 Sink 连接器的过程。

Listing 5.5 Local file Pulsar IO sink

import org.apache.pulsar.io.core.Sink;                           ❶

public class LocalFileSink implements Sink<String> {

   private String prefix, suffix;
   private BufferedWriter bw = null;
   private FileWriter fw = null;

   public void open(Map<String, Object> config,
                    SinkContext sinkContext) throws Exception {

     prefix = (String) config.getOrDefault("filenamePrefix", "test-out");
     suffix = (String) config.getOrDefault
        ("filenameSuffix", ".tmp");                              ❷

     File file = File.createTempFile(prefix, suffix);            ❸
     fw = new FileWriter(file.getAbsoluteFile(), true);          ❹
     bw = new BufferedWriter(fw);
   }

   public void write(Record<String> record) throws Exception {
     try {
        bw.write(record.getValue());                             ❺
        bw.flush();
        record.ack();                                            ❻
     } catch (IOException e) {
        record.fail();                                           ❼
        throw new RuntimeException(e);
     }
   }

   public void close() throws Exception {                        ❽
      try {
         if (bw != null)
            bw.close();
         if (fw != null)
           fw.close();
     } catch (IOException ex) {
        ex.printStackTrace();
     }
   }
}

❶ Import the source interface.

❶ 导入 source 接口。

❷ Retrieve the target filename prefix and suffix from the provided configuration properties.

❷ 从所提供的配置属性中取出目标文件名的前缀和后缀。

❸ Create the new file in the temporary directory.

❸ 在临时目录中创建这个新文件。

❹ Initialize the file and buffered writers.

❹ 初始化文件写入器和缓冲写入器。

❺ Retrieve the value from the incoming record, and write it to the open file.

❺ 从传入的记录中取出值，并把它写入已打开的文件。

❻ Acknowl-edge that we processed the message successfully, so it can be purged.

❻ 确认我们已成功处理该消息，使其可以被清除。

❼ Indicate that we weren’t able to process the message, so it can be retained and retried at a later time.

❼ 表明我们无法处理该消息，使其可以被保留并在稍后重试。

❽ Close both of the open file streams to ensure the data is flushed to disk.

❽ 关闭两个已打开的文件流，以确保数据被刷写到磁盘上。

The open method of the connector retrieves the configuration properties provided by the user and creates the empty target file inside the temp directory of the host. Next, the instance-level FileWriter and BufferedWriter variables are initialized to point to the newly created target file, while the close method will attempt to close both of the writers when the connector is stopped.

该连接器的 open 方法取出由用户提供的配置属性，并在宿主机的临时目录中创建那个空的目标文件。接下来，实例级的 FileWriter 和 BufferedWriter 变量被初始化为指向这个新创建的目标文件；而 close 方法会在该连接器被停止时尝试关闭这两个写入器。

The sink’s write method is invoked whenever a new message arrives in any of the sink’s configured input topics. The method appends the record value to the target file via the BufferedWriter’s write method before acknowledging that the message has been successfully processed. In the unlikely event that we cannot write the record’s contents to the temp file, an IOException will be thrown, and the sink will fail the message before propagating the exception.

每当有一条新消息到达该 sink 所配置的任一输入主题时，该 sink 的 write 方法就会被调用。该方法会通过 BufferedWriter 的 write 方法把记录的值追加到目标文件中，然后确认该消息已被成功处理。在我们无法把该记录的内容写入临时文件这一不大可能发生的情况下，会抛出一个 IOException，并且该 sink 会在传播该异常之前先把这条消息标记为失败。
