### 5.4.2 Debugging deployed connectors

If you encounter any errors or unexpected behavior inside a Pulsar IO connector that has been deployed, the best place to start debugging is the log files on the Pulsar worker node where the connector is running. By default, all of the connector’s startup information and captured stderr output is written to a log file. The name of the file is based on the connector name and matches the following pattern in a production environment: logs/functions/tenant/namespace/function-name/function-name-instance-id .log. In standalone mode, which is what we are currently using, the base directory is /tmp instead of /logs with the rest of the path staying the same. Let’s examine the log file for the DirectorySource connector that we created in the previous section, shown in the following listing, and review some of the information that is available to you for debugging.

如果你在一个已部署的 Pulsar IO 连接器内部遇到任何错误或意外行为，开始调试的最佳位置是该连接器所运行的那个 Pulsar worker 节点上的日志文件。默认情况下，该连接器的全部启动信息以及被捕获的 stderr 输出都会被写入一个日志文件。该文件名基于连接器名称，并且在生产环境中匹配下面这个模式：logs/functions/tenant/namespace/function-name/function-name-instance-id.log。在 standalone 模式（也就是我们目前正在使用的模式）下，基础目录是 /tmp 而不是 /logs，路径的其余部分保持不变。让我们来检查我们在上一节中创建的 DirectorySource 连接器的日志文件，如下面的清单所示，并浏览其中可供你调试的一些信息。

The first section of the log file contains the basic information about the connector, such as the tenant, namespace, name, parallelism, resources, and so on, which can be used to check whether the connector has been configured correctly or not. A little further down in the log file, you should see a message indicating which artifact file the connector was created from, which allows you to confirm that you are using the correct artifact file.

日志文件的第一部分包含关于该连接器的基本信息，例如租户、命名空间、名称、并行度、资源等等，这些信息可被用来检查该连接器是否已被正确配置。在日志文件稍往下一点的位置，你应该会看到一条消息，指出该连接器是从哪个产物文件创建出来的，这使你能够确认自己使用的是正确的产物文件。

The next section of the log file, shown in listing 5.18, contains some information about the Pulsar producers and consumers that are created on behalf of the connector and will be used to publish and consume data from the configured input and output topics. Any connectivity issues with either of these will result in errors at this point. All the log statements added to your code will follow this section and allow you to monitor the progress of your connector or see any of the exceptions that were raised.

日志文件的下一部分，如清单 5.18 所示，包含一些关于代表该连接器所创建的 Pulsar 生产者和消费者的信息，它们将被用于从所配置的输入和输出主题发布和消费数据。这两者中任何一个出现连接问题，都会在此处产生错误。你添加到自己代码中的所有日志语句都会跟在这一部分之后，使你能够监控连接器的进度，或者看到所抛出的任何异常。

When you are finished with the connector and don’t want it to run any more, you can use the bin/pulsar-admin source delete command to stop all the running instances of the connector. The only parameters you need to provide are the connector’s tenant, namespace, and name to uniquely identify the connector that you wish to delete (e.g., in order to delete the source we just created you would simply execute the following command: bin/pulsar-admin source delete —tenant public —namespace default —name directory-source).

当你用完该连接器、不希望它再继续运行时，可以使用 bin/pulsar-admin source delete 命令来停止该连接器的所有运行实例。你唯一需要提供的参数是该连接器的租户、命名空间和名称，用以唯一标识你希望删除的那个连接器（例如，要删除我们刚创建的那个 source，你只需执行下面这条命令：bin/pulsar-admin source delete —tenant public —namespace default —name directory-source）。
