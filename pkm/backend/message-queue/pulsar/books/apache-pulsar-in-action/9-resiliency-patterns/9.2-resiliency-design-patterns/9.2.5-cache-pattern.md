### 9.2.5 Cache pattern

If you would prefer *not* to write a separate function just to perform lookups, the resilency4j library also provides a way to decorate a function call with a cache as well. Listing 9.7 shows how to decorate a Java lambda expression with a cache abstraction. The cache abstraction stores the result of every invocation of the function in a cache instance and tries to retrieve a previous cached result from the cache before it invokes the lambda expression.

如果你*不*想为了做查询而专门另写一个函数，那么 resilience4j 库也提供了一种办法来为函数调用装饰上一个缓存。清单 9.7 展示了如何用一个缓存抽象来装饰一个 Java lambda 表达式。这个缓存抽象会把该函数的每一次调用结果存进一个缓存实例，并在真正调用那个 lambda 表达式之前，先尝试从缓存中取回先前缓存过的结果。

Issues and considerations

问题与考量

While this is a very useful pattern to use when interacting with an external system, such as a web service or a database, be sure to consider the following factors when implementing it inside your Pulsar function:

虽然在与外部系统（例如 Web 服务或数据库）交互时，这是一个非常有用的模式，但在自己的 Pulsar 函数中实现它时，务必考虑以下这些因素：

- This is only useful on datasets that are relatively static in nature, such as geo-encoded addresses. Don’t try caching data that is likely to change frequently; otherwise you run the risk of using incorrect data inside your application.
  这个模式只对那些性质上相对静态的数据集有用，例如已地理编码的地址。不要试图去缓存那些很可能频繁变动的数据；否则你就要冒在自己的应用里用到错误数据的风险。

- Limit the size of the cache to avoid causing out-of-memory conditions within your Pulsar function. If you need a larger cache, you should consider using a distributed cache, such as Apache Ignite.
  限制缓存的大小，以避免在你的 Pulsar 函数内部造成内存耗尽。如果你需要更大的缓存，就应当考虑使用分布式缓存，例如 Apache Ignite。

- Prevent data in your cache from becoming stale by implementing an aging policy on the data so it is automatically purged once it reaches a certain age.
  为缓存中的数据落实一套老化策略，使其在达到某个年龄后自动被清除，以防缓存中的数据变得陈旧。
