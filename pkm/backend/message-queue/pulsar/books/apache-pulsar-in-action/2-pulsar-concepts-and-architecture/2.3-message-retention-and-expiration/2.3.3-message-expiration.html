2.3.3 Message expiration

2026-10-08book

As we already discussed, Pulsar retains all unacknowledged messages indefinitely, and one of the tools we must use to prevent these messages from backing up is backlog quotas. However, one of the downsides of backlog quotas is that they only allow you to make your decision on whether to keep a message based on the total space consumed by the topic’s unacknowledged messages. As you’ll recall, one of the primary reasons for backlog quotas was to ensure that the consumer was ignoring stale data in favor of more recent data. Therefore, it would make more sense if there was a way to enforce exactly that based on the age of messages themselves. This is where message expiration policies come into play.

正如我们已经讨论过的，Pulsar 会无限期地保留所有未被确认的消息，而我们必须用来防止这些消息堆积的工具之一就是积压配额。然而，积压配额的一个缺点是：它只允许你根据主题中未确认消息所占用的总空间，来决定是否保留某条消息。正如你所记得的，积压配额的主要目的之一是确保消费者忽略陈旧数据、转而处理较新的数据。因此，如果有一种方式能够基于消息本身的存活时长来强制实现这一点，就会更加合理。这正是消息过期策略发挥作用的地方。

Pulsar supports namespace-level time-to-live (TTL) policies that allow you to have messages automatically deleted if they remain unacknowledged after a certain period of time. Message expiration is useful in situations where it is more important for the application consuming the data to be working with more recent data, rather than a complete history. One such example would be driver location data being displayed for users of a ride-sharing application while their driver is en route. The customer is more interested in the most recent location of the driver than they are in where the driver was five minutes ago. Therefore, driver location information that is older than five minutes would no longer be relevant and should be purged to allow the consumers to process only the more recent data, rather than trying to process messages that are no longer useful.

Pulsar 支持命名空间级别的存活时间（TTL）策略，使你能够让那些在一定时间之后仍处于未确认状态的消息被自动删除。在消费数据的应用更关心处理较新数据、而非完整历史记录的场合，消息过期就非常有用。一个这样的例子是：在网约车应用中，当司机正在前往乘客所在地的途中，向用户展示的司机位置数据。乘客更关心司机当前的最新位置，而不是司机五分钟前在哪里。因此，超过五分钟的司机位置信息就不再有意义，应当被清除，以便消费者只处理较新的数据，而不必去处理那些已经不再有用的消息。

Listing 2.5 Setting backlog quota and message expiration policies

./bin/pulsar-admin namespaces set-backlog-quota E-payments/payments \
--limit 2G \
--policy producer_request-hold        ❶

./bin/pulsar-admin namespaces set-message-ttl E-payments/payments \
--messageTTL 120                      ❷

❶ Defines a backlog quota with a size limit of 2 GB and producer_request_hold policy

❶ 定义一条积压配额：大小限制为 2 GB，策略为 producer_request_hold

❷ Sets the message TTL to 120 seconds

❷ 把消息 TTL 设置为 120 秒

A namespace can have both a backlog quota and a TTL policy associated with it to provide even finer control over the retention of unacknowledged messages stored inside a Pulsar topic, as shown in listing 2.5.

一个命名空间可以同时关联一条积压配额和一条 TTL 策略，从而对存放在 Pulsar 主题内的未确认消息的保留提供更精细的控制，如清单 2.5 所示。
