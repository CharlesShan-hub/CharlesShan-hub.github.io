Appendix A. Running Pulsar on Kubernetes

2026-10-08book

Kubernetes is a popular open source platform for deploying and running containerized applications at scale. It originated inside Google as a solution for managing their extensive infrastructure by automating many of the manual processes involved in deploying, managing, and scaling their applications across multiple hosts. For more information on Kubernetes, I highly recommend Kubernetes in Action by Marko Lukša (Manning, 2017).

Kubernetes 是一个广受欢迎的开源平台，用于大规模地部署和运行容器化应用。它起源于 Google 内部，是作为一种管理其庞大基础设施的方案而诞生的——办法是把跨多台主机部署、管理和扩展应用时所涉及的许多手动流程自动化。如果想进一步了解 Kubernetes，我强烈推荐 Marko Lukša 所著的《Kubernetes in Action》（Manning，2017）。

The primary purpose of Kubernetes is to schedule containers to run on a cluster of physical or virtual machines based on the available computing resources and the resource requirements of every container. A container is simply a ready-to-run software package that contains everything needed to run an application. As we saw in chapter 3, Docker is one of the most popular container technologies. So, naturally, Kubernetes can be used to schedule and run Docker containers, including those generated by the Apache Pulsar project. This allows you to run an entire Pulsar cluster and all of its components, such as Zookeeper, BookKeeper, and the Pulsar Proxy, entirely on a Kubernetes cluster. This appendix walks you through the process of doing this.

Kubernetes 的主要用途，是依据可用的计算资源以及每个容器的资源需求，把容器调度到一组物理机或虚拟机上去运行。一个容器无非就是一个随时可运行的软件包，其中包含了运行某个应用所需要的一切。正如我们在第 3 章中所看到的，Docker 是最流行的容器技术之一。因此自然地，Kubernetes 可以被用来调度和运行 Docker 容器，其中也包括由 Apache Pulsar 项目所生成的那些容器。这让你能够把一个完整的 Pulsar 集群及其全部组件（例如 Zookeeper、BookKeeper 和 Pulsar Proxy）完整地运行在一个 Kubernetes 集群上。本附录将带你走完做这件事的全过程。
