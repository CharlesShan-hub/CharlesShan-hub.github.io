### 8.1.1 Procedural programming

Traditionally, computer programs were modeled as a series of sequential operations where each operation depended upon the output of the previous operation. These programs could not be executed in parallel because they operated on the same data and, therefore, had to wait for the previous operation to complete before executing the next. Consider the logic for a basic order entry application in this programming model. You would write a simple function called processOrder that would perform the following sequence of steps (either directly or indirectly via a call to another function) to complete the process and return an order number to indicate success:

传统上，计算机程序被建模为一系列顺序执行的操作，其中每个操作都依赖于前一个操作的输出。这类程序无法并行执行，因为它们操作的是同一份数据，因此必须等前一个操作完成后才能执行下一个。我们来看看在这种编程模型下，一个基础订单录入应用的逻辑是什么样的。你会写一个名为 processOrder 的简单函数，它按以下顺序执行各个步骤（直接执行，或通过调用另一个函数间接执行），以完成整个流程并返回一个订单号来表示成功：

1.  Check the inventory for the given item to make sure it is in stock.
    检查该商品的库存，确认它有货。

2.  Retrieve customer information (shipping address, payment method, coupons, loyalty, etc.).
    获取客户信息（收货地址、支付方式、优惠券、忠诚度等）。

3.  Calculate the price, including sales tax, shipping, coupons, loyalty discounts, etc.
    计算价格，包括销售税、运费、优惠券、忠诚度折扣等。

4.  Collect the payment from the customer.
    向客户收取款项。

5.  Decrease the item count in the inventory.
    减少库存中的商品数量。

6.  Notify the fulfillment center of the order so it can be processed and shipped.
    通知履约中心该笔订单，以便其处理并发货。

7.  Return the order number to the customer.
    把订单号返回给客户。

Each of these steps acts upon the same order and depends upon the output from the previous step; for example, you cannot collect payment from the customer before you have calculated the price. Thus, each step has to wait for the previous step to complete before proceeding, making it is impossible to perform any of these steps in parallel.

这些步骤中的每一步都作用于同一笔订单，并且依赖于上一步的输出；举例来说，在你算出价格之前，是无法向客户收款的。因此，每一步都必须等上一步完成后才能继续，这使得其中任何一步都不可能并行执行。
