8.3.3 Content filter pattern

Often, it can be useful to remove or mask one or more data elements from an incoming message due to security or other concerns. The content filter pattern is essentially the inverse of the content enricher pattern because it is designed to perform this type of transformation.

出于安全或其他方面的考虑，从传入消息中移除或遮蔽一个或多个数据元素，往往是很有用的。内容过滤器模式（content filter pattern）本质上是内容丰富器模式的逆操作，因为它正是被设计用来执行这类转换的。

The OrderValidationService we discussed earlier is an example of a content filter that breaks up the incoming FoodOrder message into smaller pieces before routing them to the appropriate microservice for processing. Not only does this minimize the amount of data sent to each service, but it also hides the sensitive payment information from all the other services that do not require access to that information.

我们前面讨论过的 OrderValidationService 就是一个内容过滤器的例子：它把传入的 FoodOrder 消息拆成更小的几块，再把它们路由给相应的微服务去处理。这样做不仅把发给每个服务的数据量降到了最小，还把敏感的支付信息对那些并不需要访问该信息的其他所有服务隐藏了起来。

Consider another scenario where an event contains a sensitive data element, such as a credit card number. The content filter can detect such patterns in the messages and remove the data element entirely; mask it with a one-way hashing function, such as SHA-256; or encrypt the data field.

再考虑另一个场景：某个事件中包含一个敏感的数据元素，例如信用卡号。内容过滤器可以在消息中检测出这类模式，并把该数据元素彻底移除；或者用一个单向哈希函数（例如 SHA-256）将其遮蔽；又或者对该数据字段进行加密。
