4.1 Stream processing

2026-10-08book

While there isn’t an official definition, the term stream processing generally refers to the processing of unbounded datasets that stream in continuously from some source system. There are several datasets that occur naturally as continuous streams, such as sensor events, user activity on a website, and financial trades, which can be processed in this manner.

虽然没有官方定义，但"流处理"这个术语通常指的是对从某个源系统持续流入的无界数据集进行处理。有若干数据集天然就是以连续流的形式出现的，例如传感器事件、网站上的用户活动以及金融交易，它们都可以用这种方式来处理。

Prior to stream processing, these datasets had to first be stored in a database, file system, or other persistent storage before they could be analyzed. Often, there was an additional data processing phase required to extract the information, transform it into the correct format, and load the data into these systems. Only after the ETL process was completed was the data ready to be analyzed using traditional SQL-based or other tools. As you can imagine, there was a significant latency between the time an event occurred and when it was available for analysis. The goal of stream processing is to minimize that latency so critical business decisions can be made against the most recent data. There are three basic approaches to processing these datasets—batch processing, micro-batching, and streaming-native processing—and each take different approaches regarding how and when to process these endless datasets.

在流处理出现之前，这些数据集必须先被存放到数据库、文件系统或其他持久化存储中，然后才能被分析。通常还需要一个额外的数据处理阶段，用来抽取信息、把它转换成正确的格式，并把数据加载到这些系统中。只有在 ETL 过程完成之后，数据才可以用传统的基于 SQL 的工具或其他工具进行分析。正如你可以想见的，在一个事件发生与它可供分析之间，存在着相当大的延迟。流处理的目标就是把这种延迟降到最低，以便关键的业务决策能够基于最新的数据做出。处理这些数据集有三种基本方式——批处理、微批处理和流原生处理——对于如何以及何时处理这些无休无止的数据集，三者采取了不同的思路。
