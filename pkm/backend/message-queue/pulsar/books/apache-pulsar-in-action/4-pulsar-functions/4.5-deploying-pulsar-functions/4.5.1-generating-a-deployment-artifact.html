4.5.1 Generating a deployment artifact

2026-10-08book

When you are deploying a Pulsar function, the first step is to generate a deployment artifact that contains the function code along with all its dependencies. The type of artifact varies depending on the programming language used to develop the function.

当你部署一个 Pulsar function 时，第一步是生成一个部署产物，其中包含函数代码及其全部依赖。产物的类型取决于开发该函数所使用的编程语言。

Java SDK functions

Java SDK 函数

For Java-based functions, the preferred artifact type is a NAR (NiFi archive) file, although JAR files are also acceptable if they include all the necessary dependencies. This holds true whether you want to deploy a simple Java-native language function or one that has been developed using the Pulsar SDK. In either case, an archive file is the deployment artifact. To have your Pulsar function packaged as a NAR file, you need to include a special plugin inside your pom.xml file, as shown in the following listing, which will bundle the function class, along with all its dependencies, for you.

对于基于 Java 的函数，首选的产物类型是 NAR（NiFi archive）文件，不过如果 JAR 文件包含全部必需的依赖，也是可以接受的。无论你是想部署一个简单的 Java 语言原生函数，还是一个使用 Pulsar SDK 开发的函数，都是如此。在两种情况下，归档文件都是部署产物。要让 Pulsar 把你的函数打包成 NAR 文件，你需要在自己的 pom.xml 文件中包含一个特殊的插件，如下面的清单所示；它会为你把函数类连同其全部依赖一起打包。

Listing 4.18 Add the NAR Maven plugin to your pom.xml file

<build>
  <plugins>
      <plugin>
        <groupId>org.apache.nifi</groupId>
        <artifactId>nifi-nar-maven-plugin</artifactId>
        <version>1.2.0</version>
        <extensions>true</extensions>
        <executions>
            <execution>
                <phase>package</phase>
                <goals>
                    <goal>nar</goal>
                </goals>
            </execution>
        </executions>
      </plugin>
   . . .
  </plugins>
</build>

Once this plugin has been added to your project’s pom.xml file, all you need to do is run the mvn clean install command to generate the NAR file in your project’s target folder. This NAR file is the deployment artifact for Java-based Pulsar functions.

一旦把这个插件加入到你项目的 pom.xml 文件中，你只需运行 mvn clean install 命令，即可在你项目的 target 文件夹中生成那个 NAR 文件。这个 NAR 文件就是基于 Java 的 Pulsar function 的部署产物。

Python SDK functions

Python SDK 函数

For Python-based Pulsar functions, there are two deployment options, depending on whether or not you used the Pulsar SDK. If you didn’t use the SDK and only want to deploy a Python-native language function, then the Python source file (e.g., my-function.py) is the deployment artifact, and no further packaging is required.

对于基于 Python 的 Pulsar function，有两种部署选项，取决于你是否使用了 Pulsar SDK。如果你没有使用 SDK，只希望部署一个 Python 语言原生函数，那么那个 Python 源文件（例如 my-function.py）就是部署产物，不需要做进一步的打包。

However, if you wish to deploy a Python-based Pulsar function that depends on packages outside of the Python standard libraries, then you must first package all the required dependencies into a single artifact (ZIP file) before you can deploy it. A file named requirements.txt is required inside your Python project folder and is used to maintain a list of all the project dependencies. It is up to the developer to keep this file up to date manually. Note that pulsar-client is not needed as a dependency, as it is provided by Pulsar. When you are ready to create your Python deployment artifact, you first need to run the command shown in the following listing to download all the Python dependencies specified in the requirements.txt file into the deps folder of your Python project.

然而，如果你希望部署的基于 Python 的 Pulsar function 依赖于 Python 标准库之外的包，那么你必须先把所有必需的依赖打包进一个单独的产物（ZIP 文件），然后才能部署它。在你的 Python 项目文件夹中需要一个名为 requirements.txt 的文件，用于维护项目全部依赖的列表。保持这个文件处于最新状态是开发者自己的责任。请注意，pulsar-client 不需要作为依赖，因为它由 Pulsar 提供。当你准备好创建 Python 部署产物时，首先需要运行下面清单中所示的命令，把 requirements.txt 文件中指定的全部 Python 依赖下载到你的 Python 项目的 deps 文件夹中。

Listing 4.19 Downloading the Python dependencies

pip download \                       ❶
--only-binary :all: \                ❷
--platform manylinux1_x86_64 \       ❸
--python-version 37 \                ❹
-r requirements.txt \                ❺
-d deps                              ❻

❶ Use the pip package manager for Python.

❶ 使用 Python 的 pip 包管理器。

❷ We need the binary version of all dependencies.

❷ 我们需要所有依赖的二进制版本。

❸ Specify the target execution platform operating system.

❸ 指定目标执行平台的操作系统。

❹ Specify the Python version.

❹ 指定 Python 版本。

❺ Relative path to the requirements.txt file

❺ requirements.txt 文件的相对路径

❻ Target download directory.

❻ 目标下载目录。

After the download is complete, you need to create a destination folder with the desired package name (e.g., echo-function). Next, you must copy over both the src and deps folders into it and compress the folder into a ZIP archive. The ZIP file generated from the command in the following listing is the deployment artifact for Python-based Pulsar functions.

下载完成之后，你需要用期望的包名（例如 echo-function）创建一个目标文件夹。接下来，你必须把 src 和 deps 两个文件夹都拷贝进去，并把该文件夹压缩成一个 ZIP 归档。由下面清单中命令所生成的这个 ZIP 文件，就是基于 Python 的 Pulsar function 的部署产物。

Listing 4.20 Packaging a Python-based Pulsar function for deployment

mkdir -p /tmp/echo-function                           ❶

cp -R deps /tmp/echo-function/
cp -R src /tmp/echo-function/                         ❷

zip -r /tmp/echo-function.zip /tmp/echo-function      ❸

❶ Create a new target directory for the function dependencies and source.

❶ 为函数的依赖和源码创建一个新的目标目录。

❷ From inside the Python project folder, copy over dependencies and source.

❷ 从 Python 项目文件夹内部，把依赖和源码拷贝过去。

❸ Use the zip command to create a ZIP file containing the contents of the target directory.

❸ 使用 zip 命令创建一个包含该目标目录内容的 ZIP 文件。

Golang SDK functions

Golang SDK 函数

For Golang-based Pulsar functions, the preferred artifact type is a single binary-executable file that contains the machine byte code for your function along with all the supporting code needed to execute the code on any computer, regardless of whether that system has the .go source files or even a Go installation. You can use the Go toolchain, as shown in the following listing, to generate this binary executable file.

对于基于 Golang 的 Pulsar function，首选的产物类型是一个单独的二进制可执行文件，它包含你函数的机器字节码，以及在任何计算机上执行该代码所需的全部支撑代码，而不管那台系统上是否有 .go 源文件、甚至是否安装了 Go。你可以使用 Go 工具链来生成这个二进制可执行文件，如下面的清单所示。

❶ Make sure you are in the project directory.

❶ 确认你位于项目目录中。

❷ Use the Go build command to generate the binary executable.

❷ 使用 Go build 命令生成该二进制可执行文件。

❸ Go 会自动下载你需要的任何包，并把它们包含进该二进制文件。

❻ The executable binary that was generated

❻ 所生成的可执行二进制文件

If you are running macOS or Linux, the binary executable file will be generated inside the directory where you run the command, and it will be named after the source file. This is the artifact that must be deployed to run the Golang-based function inside of Pulsar.

如果你运行的是 macOS 或 Linux，该二进制可执行文件会在你运行命令的那个目录内被生成，并以源文件的名字命名。这就是为了在 Pulsar 内部运行基于 Golang 的函数而必须被部署的产物。
