12.3 Edge analytics

2026-10-08book

The practice of performing some or all of the data analysis on infrastructure outside of a traditional data center or cloud computing environment is commonly referred to as edge analytics and differs from traditional analytics in a few other key ways that must be kept in mind when you are designing your overall analytics strategy. For starters, the analysis must be done on streaming datasets, where each piece of information will be provided to your Pulsar function only once. Since there is very limited physical disk space in an edge environment, these sensor values are not retained, and thus cannot be reread at a future point in time. If you wanted to determine the average reading of a sensor over the previous hour in a cloud environment, for example, you could simply execute an SQL query to calculate it for you from the historical data. This is not an option with edge analytics. Another big difference is that the closer you move the processing to the sensors, the less information you have in your dataset, which makes the detection of patterns between sensors that are not co-located within the range of the same IoT gateway impossible.

在位于传统数据中心或云计算环境之外的基础设施上执行部分或全部数据分析，这种做法通常被称为边缘分析（edge analytics）；它在另外几个关键方面也与传统分析有所不同，而这些方面在你设计整体分析策略时必须牢记在心。首先，分析必须在流式数据集上进行——在那里，每一条信息只会被提供给你的 Pulsar 函数一次。由于边缘环境中的物理磁盘空间非常有限，这些传感器值并不会被留存，因而也无法在未来的某个时间点被重新读取。举例来说，假如你想在某个云环境中确定某个传感器在过去一小时内的平均读数，你只需执行一条 SQL 查询，让它依据历史数据替你算出来即可。而在边缘分析中，这不是一个可选项。另一个重大差异是：你把处理搬得离传感器越近，你的数据集中所包含的信息就越少；这使得那些并未共处同一个 IoT 网关覆盖范围内的传感器之间的模式检测变得不可能。
