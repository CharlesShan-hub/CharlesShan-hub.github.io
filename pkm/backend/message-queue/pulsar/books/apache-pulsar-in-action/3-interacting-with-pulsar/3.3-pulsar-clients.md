## 3.3 Pulsar clients

Pulsar provides a CLI tool called *pulsar-client* that allows you to send and receive messages from a topic in a running Pulsar cluster. This tool also resides inside the bin folder of your Pulsar installation, and thus, we will need to use the docker exec command again to interact with this tool.

Pulsar 提供了一个名为 *pulsar-client* 的 CLI 工具，它使你能够在一个运行中的 Pulsar 集群里向主题发送和接收消息。这个工具同样位于你的 Pulsar 安装目录的 bin 文件夹中，因此我们还需要再次使用 docker exec 命令来与它交互。

Since the topic has already been created, we can start by first attaching a consumer to it, which will establish a subscription and ensure that no messages are lost. This can be accomplished by running the command shown in the following listing. The consumer is a *blocking script*, meaning it will keep consuming messages from the topic until the script is stopped by you (with Ctrl+C).

由于主题已经创建好了，我们可以先着手把一个消费者挂到它上面，这将建立一个订阅并确保不会有消息丢失。这可以通过运行下面清单中所示的命令来完成。该消费者是一个*阻塞式脚本*，意思是它会持续从主题消费消息，直到你（用 Ctrl+C）停止该脚本。

Congratulations, you have just successfully sent your first messages using Pulsar! Now that we have confirmed that our local Pulsar cluster is working and capable of sending and receiving messages, let’s look at some more realistic examples, using various programming languages. Pulsar provides a simple and intuitive client API that encapsulates all the broker-client communication details from the user. Due to the popularity of Pulsar, there are several language-specific implementations of this client, including Java, Go, Python, and C++, just to name a few. This allows each team in your organization to use whatever language they like to implement their services.

恭喜，你刚刚用 Pulsar 成功发送了你的第一批消息！既然我们已经确认本地 Pulsar 集群工作正常、能够收发消息，那就来看一些更贴近实际的示例，使用不同的编程语言。Pulsar 提供了一个简单直观的客户端 API，它把所有 broker 与客户端之间的通信细节都对用户封装了起来。由于 Pulsar 的流行度，该客户端有若干种语言特定的实现，包括 Java、Go、Python 和 C++ 等等，此处仅举几例。这使你组织中的每个团队都能用自己喜欢的任何语言来实现其服务。

While there are significant discrepancies in the features supported by the official Pulsar client libraries based on the programming language you chose (please refer to the official client documentation for details), under the covers they all support transparent reconnection and/or connection failover to brokers, queuing of messages until acknowledged by the broker, and heuristics, such as connection retries with backoff. This allows the developer to focus on the messaging logic, rather than having to handle connection exceptions in their application code.

虽然官方 Pulsar 客户端库所支持的特性会因你选择的编程语言而存在显著差异（详情请参阅官方客户端文档），但在底层，它们都支持对 broker 的透明重连和/或连接故障转移、在被 broker 确认之前对消息进行排队，以及一些启发式策略，例如带退避的连接重试。这使开发者能够专注于消息逻辑，而不必在自己的应用代码中处理连接异常。
