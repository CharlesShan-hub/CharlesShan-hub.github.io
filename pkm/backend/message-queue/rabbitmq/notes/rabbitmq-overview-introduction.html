RabbitMQ 概述

RabbitMQ 简介

  1. 官网地址：https://www.rabbitmq.com/
  2. logo：

  1. RabbitMQ 是一款基于 AMQP、由 Erlang 语言开发的消息队列产品。2007 年由 Rabbit 技术公司发布了 1.0 版本。

RabbitMQ 的内部体系结构

生产者 Producer 与消费者 Consumer

消息的发送端被称为生产者 Producer

消息的接收端被称为消费者 Consumer

Producer 和 Consumer 都可以是 Spring Cloud 当中的一个微服务

消息队列中的 Connection 与 Channel

当生产者发送消息的时候，或者消费者接收消息的时候，都必须与消息队列服务器建立连接，这个连接被称为 Connection。但是这个 Connection 是基于 TCP 协议的，如果每一次连接都进行三次握手，那效率就会很低，怎么能够提高效率呢？如果让 Connection 复用就可以提升效率了，因此在 Connection 中弄了很多 Channel。

Connection（连接）：重量级的TCP长连接

  • 这是一个建立在TCP协议之上的网络连接。创建和销毁它需要三次握手和四次挥手，开销很大。

Channel（信道）：轻量级的逻辑连接

  • Channel是建立在一个Connection内部的虚拟连接。它是一个逻辑概念，不存在于TCP层。
  • 创建和销毁Channel的开销极低，因为它不需要进行网络握手。
  • 它的主要作用是实现多路复用，允许在单个Connection上同时进行多个不同的消息流操作。

现实生活中的例子：

  • Connection 就像是在两个城市之间修建的一条高速公路。修路的成本很高（TCP握手），但一旦修好，就可以长期使用。
  • Channel 就像是这条高速公路上的一条条独立车道。你可以在一条高速路上轻松地划出多条车道（创建Channel），每条车道都可以同时跑不同的车（传输不同的消息），互不干扰。开辟新车道的成本很低，不需要重新修路。

Broker

每个 RabbitMQ 的实例被称为 Broker。就是 RabbitMQ 主体服务器本身，负责接收和分发消息。在实际生产环境中，为了实现高可用和高性能，我们通常不会只使用一个 Broker。我们会将多个 Broker 实例组成一个集群。

Virtual Host

虚拟分组，在每个 Broker 实例中可以划分多个虚拟分组（Virtual Host 可以有很多个，但一般一个分布式系统对应一个 Virtual Host）。

用户在自己的 Virtual Host 中使用 RabbitMQ。

在实际开发中，通过 Virtual Host 区分不同项目。

Exchange 与 Queue

翻译为交换机，是消息到达之后的第一站。也就是发送消息的时候，先把消息发送到交换机上。再通过交换机这个中转站把消息发到队列（Queue）上。

注意：Exchange 不负责存储消息，只是消息的中转站。真正存储消息的是 Queue。如果被消费端取走的话，也是从队列 Queue 中删除。

Exchange 可以有很多个。Queue 也可以有很多个。

交换机是如何知道将消息发送到哪个队列呢？就看 Exchange 和 Queue 之间的绑定关系（路由键）。

Exchange 可以绑定一个队列 Queue，也可以绑定多个队列 Queue。

一条消息的发送与接收流程

想象一下，你是一个生产者（Producer），比如一个订单微服务，需要发送一条“订单创建”的消息。你首先需要与远方的RabbitMQ Broker（消息中转局）建立一条Connection（好比在两个城市间修建了一条高速公路）。为了高效，你在这条公路上轻松地开辟了一条Channel（一条专用车道）。你沿着这条车道，把消息寄给了Broker里的一个Exchange（中央分拣中心）。Exchange根据你提供的地址（路由键）与 Queue（暂存仓库）的绑定关系，将消息精准地投递到“订单队列”仓库中。此时，作为消费者（Consumer） 的库存微服务，也建立了一条到Broker的高速公路和自己的车道，它一直在“订单队列”仓库边守候，消息一来便立刻取走处理。所有这些组件（订单微服务、库存微服务、订单队列）都隔离在同一个Virtual Host（例如“电商项目组”）内，与其它项目互不干扰。至此，消息成功完成了一次从发送到接收的旅程。

对于编程来说，如何实现呢？

  • 对于生产者来说
    • 声明交换机（创建交换机：如果该交换机已存在，则直接使用，不需要重复创建）
    • 声明队列（创建队列：如果该队列已存在，则直接使用，不需要重复创建）
    • 使用路由键将交换机和队列绑定在一起
    • 发送消息时只需要指定：交换机 和 路由键
  • 对于消费者来说
    • 只需要指定哪个队列就行。

安装 RabbitMQ

第一步：拉取镜像

docker pull rabbitmq:3.13-management

第二步：创建 RabbitMQ 容器（基于我们之前大健康项目的网络 IP 来创建）

docker run -d --name mq \
--net dajiankang --ip 172.16.0.13 \
-p 5672:5672 \
-p 15672:15672 \
-e RABBITMQ_DEFAULT_USER=admin \
-e RABBITMQ_DEFAULT_PASS=123456 \
-e TZ=Asia/Shanghai \
-m 450m \
--restart unless-stopped \
rabbitmq:3.13-management

5672 端口是和客户端程序交互使用的。(将来生产者端和消费者端都是通过 5672 访问 RabbitMQ)

15672 是 web 管理的端口。

第三步：端口转发

在 Oracle VirtualBox软件中配置端口转发。这样在 windows 系统上就可以使用 localhost方式访问了。

windows 端口 虚拟机端口 docker 端口
5672 5672 5672
15672 15672 15672

第四步：打开 Web 管理界面：http://localhost:15672/
