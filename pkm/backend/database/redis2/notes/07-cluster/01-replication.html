复制（Replication）

来源：《Redis设计与实现》第 15 章；配置部署参考 d:\project\PKM\pkm\backend\database\redis\notes\cluster.md

概述

Redis 的主从复制功能允许从服务器精确地复制主服务器的数据。

旧版复制功能的实现（Redis 2.8 之前）

使用 SYNC 命令，分为两步：

  1. 同步：从服务器向主服务器发送 SYNC 命令
  2. 主服务器执行 BGSAVE 生成 RDB 文件
  3. 主服务器将 RDB 文件发送给从服务器
  4. 从服务器载入 RDB 文件
  5. 命令传播：主服务器将写命令发送给从服务器执行

缺陷：断线重连后必须执行完整重同步（全量 RDB），低效。

新版复制功能的实现（Redis 2.8+）

使用 PSYNC 命令代替 SYNC，支持两种模式：

完整重同步

用于初次复制，与旧版 SYNC 流程相同（生成并发送 RDB 文件）。

部分重同步

用于断线后重复制，只需将断线期间的写命令发送给从服务器。

部分重同步的三大核心

1. 复制偏移量

  • 主服务器每次传播 N 字节数据 → 偏移量 +N
  • 从服务器每次收到 N 字节数据 → 偏移量 +N
  • 通过对比偏移量判断主从是否一致

2. 复制积压缓冲区

  • 主服务器维护的一个 固定长度 FIFO 队列（默认 1MB）
  • 主服务器传播写命令的同时，也将命令入队到缓冲区
  • 从服务器重连后，若断线期间的偏移量仍在缓冲区中 → 执行部分重同步
  • 若已不在缓冲区中 → 执行完整重同步
  • 缓冲区大小建议：2 × 平均断线时间 × 每秒写入量

3. 服务器运行 ID

  • 每个 Redis 服务器启动时生成 40 位十六进制运行 ID
  • 从服务器初次复制时保存主服务器的运行 ID
  • 断线重连后，比较运行 ID：
  • 相同 → 尝试部分重同步
  • 不同 → 执行完整重同步

PSYNC 命令

从服务器 → 主服务器：PSYNC <runid> <offset>
  • 主服务器返回 +FULLRESYNC <runid> <offset> → 完整重同步
  • 主服务器返回 +CONTINUE → 部分重同步
  • 主服务器返回 -ERR → 主服务器版本低于 2.8，从服务器使用 SYNC

复制的实现流程

  1. 设置主服务器地址和端口（SLAVEOF）
  2. 建立套接字连接
  3. 发送 PING 检查通信状态
  4. 身份验证
  5. 发送端口信息
  6. 同步（PSYNC）
  7. 命令传播

心跳检测

  • 从服务器默认每秒向主服务器发送 REPLCONF ACK <replication_offset>
  • 作用：
  • 检测主从连接状态
  • 辅助实现 min-slaves 选项
  • 检测命令丢失（主服务器发现偏移量不一致时重发）
