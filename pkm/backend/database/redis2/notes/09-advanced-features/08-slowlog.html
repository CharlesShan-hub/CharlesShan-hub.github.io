慢查询日志

来源：《Redis设计与实现》第 23 章

概述

慢查询日志功能用于记录执行时间超过指定阈值的命令请求，方便开发者定位性能瓶颈。

相关配置

配置项 说明 默认值
slowlog-log-slower-than 执行时间超过多少微秒的命令会被记录 10000（10ms）
slowlog-max-len 慢查询日志最多保存多少条 128

慢查询记录的保存

服务器状态中维护一个链表保存所有慢查询日志：

struct redisServer {
    list *slowlog;                 // 慢查询日志链表
    long long slowlog_entry_id;    // 下一条日志的 ID
};

每条日志包含： - ID（递增） - 命令执行完成的 UNIX 时间戳 - 命令执行消耗的时间（微秒） - 命令及其参数

慢查询日志的阅览和删除

命令 说明
SLOWLOG GET [n] 获取最近的 n 条慢查询日志
SLOWLOG LEN 获取慢查询日志数量
SLOWLOG RESET 清空所有慢查询日志

添加新日志

在命令执行完毕后（call() 函数中），服务器会检查该命令的执行时间：

  • 如果执行时间 > slowlog-log-slower-than，则创建一条日志并添加到 slowlog 链表头部
  • 如果链表长度超过 slowlog-max-len，则删除尾部（最旧）的日志
